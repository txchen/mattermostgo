# Run log: first working version, 2026-11-12

The decision trail of the session that took the repo from design to a
working client. Mode: single agent. Subagents were not installed, so no
step had an independent review: `BLOCKED: independent review`.

## Definition of done

A native window that adds a server, logs in with a password and MFA,
shows teams, categories and channels with unread state, reads and sends
posts in channels, DMs and threads, and receives posts, reactions,
typing and read state live. Checked against a real Mattermost server,
not only fakes.

## Bugs the checks found

- The generated sequences found that a retry after the server had
  already confirmed a post duplicated it, that a reloaded page left the
  pending copy of a confirmed post, and that deleting a root post
  skipped replies while it edited the slice it iterated.
- `http.Client` refuses `ws://` URLs, so the socket dials `http(s)`
  with Upgrade headers, and forces HTTP/1 because HTTP/2 has no Upgrade.
- A composer bound to a local copy of its draft lost `SetText("")`;
  drafts are now stable pointers.
- Opening a channel loaded a second page at once, since an unlaid list
  reports row 0 as visible.
- The real app showed no live posts. The cause was the Keychain: a
  rebuilt unsigned binary waits for a permission prompt, and `Start`
  read it on the main thread while frames kept drawing, so the session
  never started and the view met a server list with no current server.
  Keychain access now happens off the main thread.

## Decisions

- Replies show in the channel and counts include them (ADR 0004).
- No dependencies beyond mygo and the standard library. The WebSocket
  client is ~200 lines in `internal/mm/websocket.go`.
- Emoji names come from iamcal/emoji-data v16.0.0, generated by
  `internal/markdown/gen_emoji.go` (1,972 names).
- Mentions are rewritten into links before parsing, because mygo's
  mention extension follows GitHub's login rules and cuts `@first.last`.
- No Docker here, so the dev server is built from source
  (`scripts/devserver.sh`). It needed two symlinks into
  `/opt/homebrew/{share,lib}/postgresql@17`, made by hand, since
  Homebrew could not link postgresql@17 beside libpq.

## Bugs the real window found

- Typing @ looped: each user search's answer cleared the word, so the
  next frame searched again, forever, and Enter met an empty word.
  Searches now go once per prefix (regression in TestMentionAutocomplete).
- A completed word stayed dismissed, so the same @bo later sent "@bo".
- Option+Up/Down did nothing with the focus in the composer.
- Text typed right after a key that set the composer's text was lost:
  TextKey.SetText acts as the app setting the value at the next frame,
  over what was typed meanwhile. Keys now note their edit, and the build
  makes it with ReplaceText.
- The Keychain prompt for a rebuilt ad-hoc build still blocks the first
  token read (now off the main thread, the login form waits). Signed
  release builds keep one identity, so they should not ask. Not checked:
  no Developer ID here.

## Scrolling 5,000 posts, real window

`scripts/seed -big 5000` posts eight shapes in turn (plain, markdown,
mentions, lists, code blocks, long text, CJK, tables).
`scripts/perf/bigscroll.sh` scrolls up until all 84 pages load (4 s),
then down and up through the channel, with MYGO_FRAME_STATS=all, the
window frontmost on the GPU, Apple Silicon, 2x display:

| phase | frames | p50 | p90 | p99 | max |
|---|---:|---:|---:|---:|---:|
| loading pages | 174 | 4.8 ms | 6.5 ms | 9.6 ms | 11.8 ms |
| scrolling | 203 | 6.2 ms | 6.9 ms | 9.0 ms | 13.3 ms |

Layout is most of a frame (p50 3.0 ms scrolling): rows coming into view
are laid out for the first time. Every frame fits 60 Hz (16.7 ms); p90
fits 120 Hz (8.3 ms), the worst frames do not. RSS 140 MB with the
channel open, 162 MB with all 5,000 posts loaded, 188 MB after
scrolling through them: a channel keeps every page it loaded, which the
LRU of channels does not bound.

An earlier run before the redesign measured p90 11.4 ms, but with the
window not frontmost; the two are not comparable, and the gain is not
claimed. The plain-text path (posts without Markdown skip the Markdown
view) is 9% faster per frame in the windowless benchmark when every post
is plain (2.17 vs 2.38 ms), and no different on the mixed channel;
TestPlainTextIsOneParagraph checks 20,000 generated messages (300,000
once) against mygo's parser that the path shows what Markdown would.

## 0.1.1 against 0.4.0 work, same machine, 2026-11-13

`scripts/perf/compare.sh` on Developer ID signed debug builds of v0.1.1
and of the 0.4.0 tree, logged in as alice, two runs each, then
`go test -bench ScrollBigChannel -count=5 ./internal/view` on both trees.

| | 0.1.1 | 0.4.0 |
|---|---:|---:|
| scrolling p50, run 1 / 2 | 6.2 / 6.1 ms | 5.3 / 5.3 ms |
| of it, build + layout p50 | 0.5 + 3.0 ms | 0.6 + 3.0 ms |
| of it, present p50 | 1.2 ms | 0.3 ms |
| windowless frame, median of 5 | 2.86 ms | 2.94 ms |
| RSS after opening Big Channel | 134 MB | 146 MB |
| RSS after scrolling all 5,000 posts | 194-196 MB | 173-175 MB |
| idle in the background, 60 s | 0.01 s CPU, 0 frames | 0.01 s CPU, 0 frames |

The work of the client per frame is the same: build and layout did not
move, and the windowless frame is 3% slower (the new per-post parts:
the profile buttons, the text watched for clicks, the pinned and saved
marks). The real-window frames are faster only in the present phase,
which the client does not do; why it dropped is not known. Opening
costs 12 MB more, a guess being the preferences, the followed threads
of every team and the larger emoji table loaded at start; the cause is
not measured. Idle stays at zero frames.
